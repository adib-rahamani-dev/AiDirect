اتصال این کامپیوتر به Neon در تست‌های حجیم با تأخیر، DNS و قطع شبکه مواجه شد؛ مسیر درج با RETURNING سبک‌تر و timeoutها مشخص شدند. CI با PostgreSQL جدا همهٔ آزمون‌ها را گذراند. TLS یا اعتبارسنجی امضا غیرفعال نشده‌اند.

## قابلیت آماده

- ورود ایمیل و scrypt، نشست هش‌شدهٔ قابل ابطال و انقضای ۸ساعته.
- دعوت دو‌ساعته با پذیرش یک‌بارمصرف؛ مالک پیج به پنل مدیر دسترسی نمی‌گیرد.
- OAuth با state وابسته به مرورگر/دعوت، توکن رمزنگاری‌شده، فرم رسانه/کلمه/متن/لینک و پیش‌نمایش.
- webhook raw-body HMAC، صف پایدار، یکتایی، lease و قرنطینهٔ unknown.
- retry محدود برای خطای صریح موقت/rate limit؛ ارسال نامعلوم خودکار تکرار نمی‌شود.
- guard پایدار برای فاصلهٔ یک‌ساعتهٔ تلاش refresh در serverless.
- قطع اتصال و purge تأییدشده؛ کامنت‌های قبل از اتصال تازه پردازش نمی‌شوند.
- راهنمای عمومی، حریم خصوصی آزمایش و دستورالعمل حذف با بیان کارهای باز.

## اجرای آزمایش

مشخصات ورود فقط در فایل خصوصی .local/operator-login.txt است و چاپ نشده است. فایل خالی .env.meta.local برای واردکردن App ID و App Secret **جدید و Resetشده** آماده است. دستورها و URLهای دقیق در [راهنمای استقرار](docs/deployment.fa.md) هستند.

زمان‌بند با npm run worker:remote از این کامپیوتر اجرا می‌شود و پیش‌فرض بعد از دو ساعت متوقف می‌شود. فعلاً دائمی اجرا نشده است. بدون heartbeat اخیر، health و پنل عمداً worker را missing/متوقف نشان می‌دهند؛ صف حذف نمی‌شود. این سازوکار فقط برای آزمایش رایگان است.

Push و CI برقرارند؛ استقرار دستی CLI انجام می‌شود. اتصال خودکار GitHub→Vercel نیاز به دسترسی GitHub خود مالک در Project Settings → Git دارد.

## قدم‌های وابسته به مالک

حساب Facebook/Developer و اپ معتبر، حساب Instagram سالم و حرفه‌ای عمومی، پذیرش Tester، Reset کلید افشاشدهٔ قبلی و تنظیم کلیدها فقط محلی/سرور؛ سپس ثبت callback، ورود رسمی، رسانهٔ واقعی، **ارسال دستی و مشاهدهٔ پیام** و بعد **کامنت/webhook واقعی و مشاهدهٔ پیام دوم**.

سطح دسترسی/وضعیت انتشار لازم برای webhook باید طبق مستندات و داشبورد همان اپ کامل باشد. اجازهٔ کشور/کسب‌وکار حدس زده نشده است.
