# اثبات اتصال با Sendbox / BoxAPI

تاریخ بررسی مستندات و API: 2026-10-18.

Sendbox یک واسطهٔ بیرونی است. اتصال مستقیم اپ شخصی متا در AiDirect همچنان مسیر جداست و هنوز اثبات نشده. سایت Sendbox استفاده از API رسمی متا را اعلام می‌کند؛ بررسی مستقل وضعیت اپ، قرارداد یا مجوزهای تجاری ارائه‌دهنده انجام نشده است.

## بررسی واقعی انجام‌شده

با توکن تحویلی کاربر، درخواست‌های فقط‌خواندنی `GET /service/info` و `GET /service/accounts` روی `https://api.sendbox.chat/api/v1`، هدر `X-Api-Key`، پاسخ HTTP 200 و success=true دادند. هیچ پیجی متصل نبود؛ سقف پلن یک پیج بود. دامنه و redirect هنوز مقادیر پیش‌فرض BoxAPI بودند. فقط این خواندن‌ها واقعی‌اند؛ هیچ پیام یا اکشن پولی ارسال نشد.

سپس با اجازهٔ کاربر، Domain، Redirect URL و Webhook URL در پنل موجود BoxAPI ذخیره شدند. خواندن مجدد `/service/info`، دامنهٔ AiDirect و callback جدید را تأیید کرد. دو Secret خصوصی روی Vercel ثبت شدند. اتصال پیج همچنان صفر بود؛ این تغییر تنظیمات، اثبات ارسال نیست.

## تنظیمات سرویس

در «تنظیمات API رسمی اینستاگرام» این مقادیر را ثبت کن:

| فیلد           | مقدار                                                    |
| -------------- | -------------------------------------------------------- |
| Domain         | `https://aidirect-kappa.vercel.app`                      |
| Redirect URL   | `https://aidirect-kappa.vercel.app/api/sendbox/callback` |
| Webhook URL    | `https://aidirect-kappa.vercel.app/api/sendbox/webhook`  |
| متد webhook    | `POST`                                                   |
| Webhook Secret | مقدار ساخته‌شده توسط خود سرویس؛ مطابق تنظیم خصوصی سرور   |

این سرویس به Meta Verify Token نیاز ندارد. از `/api/meta/webhook` برای Sendbox استفاده نکن.

رازهای سرور در `.env.sendbox.local` نگهداری می‌شوند. این فایل از Git و بستهٔ استقرار حذف است. متغیرهای لازم `SENDBOX_API_KEY` و `SENDBOX_WEBHOOK_SECRET` هستند. اسکریپت `node scripts/sync-sendbox.mjs` آن‌ها را از stdin به Secretهای production پروژهٔ موجود Vercel می‌فرستد؛ سپس redeploy لازم است. لینک ورود از `/service/info` خوانده می‌شود؛ نیازی به کپی یا ذخیرهٔ آن در کد/کلاینت نیست. توکن‌ها و لینک ورود قبلاً در چت ارسال شده‌اند؛ تعویض آن‌ها در پنل سرویس توصیه شده، اما انجام‌شدنش تأیید نشده است.

## اتصال و بررسی

1. در `/admin` با حساب مدیریت وارد شو. پنل وضعیت واقعی اتصال، دعوت‌ها و رویدادها را نشان می‌دهد.
2. برای پیج خودت «اتصال اینستاگرام» و برای پیج دیگری «ساخت لینک دعوت» را بزن. لینک خصوصی دو ساعت و یک پذیرش اعتبار دارد؛ دعوت تازه، قبلی را لغو می‌کند.
3. صاحب پیج در `/connect/instagram` دعوت را می‌پذیرد و «ادامه در اینستاگرام» را می‌زند. رمز مدیر لازم نیست. رمز Instagram فقط در صفحهٔ رسمی Instagram وارد می‌شود؛ اتصال از طریق Sendbox است.
4. callback با state یک‌بارمصرف، cookie و همان نقش مدیر/دعوت بررسی می‌شود. مالکیت، فعال‌بودن و انقضای account_id از API احرازشده تأیید می‌شوند. مدیر به `/admin` و مهمان به `/connect/instagram` برمی‌گردد؛ حساب دیگر بدون قطع قبلی جایگزین نمی‌شود.
5. با حساب دوم کامنت تازه بگذار؛ «تازه‌سازی» باید رویداد کامنت را نشان دهد. دریافت امضاشده، ارسال پیام را ثابت نمی‌کند. پنل مستقیم Meta/شبیه‌سازی در `/proof` مستقل است.

## قرارداد webhook

امضا با متا فرق دارد: هدرهای `X-BoxApi-Signature` و `X-BoxApi-Timestamp`؛ HMAC-SHA256 روی `timestamp + '.' + raw_body`، مقایسهٔ timing-safe و اختلاف زمان حداکثر ۳۰۰ ثانیه. تغییر بدنه، امضای گمشده/نامعتبر و timestamp نامعتبر/قدیمی رد می‌شوند. در نبود سکرت، endpoint با 503 بسته می‌ماند؛ درخواست نامعتبر 401 می‌گیرد.

رویداد فقط برای UUID پیج متصل و معتبر ذخیره می‌شود. DM، echo و رخدادهای نامرتبط نادیده گرفته می‌شوند. `event_id` کلید یکتا دارد و قبل از 200 در PostgreSQL ثبت می‌شود؛ DB ناموجود 503 می‌دهد تا سرویس retry کند. بدنه تا ۱ MiB محدود است. دادهٔ comment و اکشن‌های مشخص برای بررسی قرارداد در AES-GCM رمز می‌شود؛ در گزارش پنل فقط نوع/زمان می‌آید. دادهٔ رمز‌شده پس از ۲۴ ساعت در اولین اجرای پاک‌سازی (webhook، مشاهدهٔ پنل، یا job زمان‌بند) حذف می‌شود؛ بدون اجرای پردازش، حذف فیزیکی رأس ۲۴ ساعت تضمین ندارد. رکورد کمینهٔ event_id برای dedupe باقی می‌ماند. دکمهٔ قطع اتصال محلی، داده‌های این مسیر را پاک می‌کند؛ لغو دسترسی از خود سرویس/Instagram جداست.

## قدم بعد از دریافت واقعی

`POST /service/actions/private_reply` با `account_id`، `comment_id` و `message` برای پاسخ خصوصی مستند شده است. `send_message` جایگزین آن نیست. `list_posts` و بعضی عملیات پاسخ آسنکرون دارند؛ HTTP 2xx آن‌ها به معنی نتیجهٔ نهایی یا دریافت پیام نیست.

هنوز هیچ فراخوانی private_reply، ارسال واقعی، پردازش نتیجهٔ آسنکرون یا اتوماسیون Sendbox پیاده/فعال نشده است. پس از اتصال پیج و دریافت نمونهٔ معتبر، باید ساختار واقعی comments، timestamp ساخت کامنت، نتیجهٔ list_posts و شناسهٔ هم‌بستگی اکشن بررسی شود؛ سپس ارسال دستی یکتا با قرنطینهٔ نتیجهٔ نامعلوم اضافه و مشاهدهٔ پیام در حساب دوم ثبت شود. پس از اثبات دستی، اتوماسیون کامنت تازه فعال می‌شود. قاعدهٔ مستقیم متا و worker شبیه‌سازی، SendboxEvent را مصرف نمی‌کنند.
